# Contributing to NGSI-LD4AI

This document provides contribution guidelines for NGSI-LD4AI.

## Contributor License Agreement (CLA)

Before we can accept contributions, please sign one of the following CLAs:

- [ScorpioBroker Entity Contributor License Agreement](./ScorpioBroker-Entity_CLA_final.pdf)
- [ScorpioBroker Individual Contributor License Agreement](./ScorpioBroker-Individual_CLA_final.pdf)

### Note on CLA files

NEC considers Scorpio and NGSI-LD4AI as a single open source component for internal governance. Therefore, the same CLA files are used for both, with Scorpio as the main component and NGSI-LD4AI as a subcomponent.

## Ground rules

- Be respectful and constructive in all discussions.
- Keep discussions in public issues/PRs whenever possible.
- Security issues should be reported privately to maintainers first.

## How to contribute

For small fixes (typos, minor docs updates), open a PR directly.

For larger changes (new tools, behavior changes, architecture work), open an issue first to discuss scope.

## Pull request expectations

- Do not commit directly to the main branch; use pull requests.
- Link related issues in the PR description when applicable.
- Include tests and documentation updates when behavior changes.
- Keep PRs small enough to review efficiently.
- Address review comments before merge.

## Technical expectations

- Primary language is Java (Quarkus + Maven).
- Keep code simple, readable, and maintainable.
- Avoid unnecessary dependencies.
- Follow existing project structure and conventions.
- Do not commit binaries generated by builds.

## Build and verification

Run the project build before submitting:

```bash
mvn clean package
```

Use native build checks when your change may affect native packaging:

```bash
mvn clean package -Pnative
```
